# canon 终端试聊

`moirai canon test`（即 `run_canon_chat.py`）是独立的本机试聊入口，用来在真实 Bot 接入之前观察“检索到的片段 → 阿米娅回复”。它不经过 AstrBot、Core Event Protocol、Moirai 原有聊天记忆或正式的 B6–B9 注入路径，因此不能代替 [canon.md](canon.md) 里的 Bot 验收。本文件描述终端**当前**的行为，是证据预算和每轮流程的唯一出处；各轮改动的动机和测量结果见 [canon 对话质量](canon-dialogue-quality.md)（英文，按日期记录）和 [canon 检索实验](canon-retrieval-experiment.md)。代码结构和迁移到正式路径的指引见 [canon 运行时结构](canon-runtime-architecture.md)。

## 启动与选项

在终端直接运行（沿用已有的 `~/.local/bin/moirai` 命令）：

```bash
moirai canon test
```

- **数据库**：默认读 V11 全库试聊副本 `.dev_data/canon/v11/chat/full-20260928.sqlite`（618 个场景、4,903 个事件，已导入干员档案；复制自 `v11/all/build/canon.sqlite`，按 `imported_at` 找到该构建目录下的向量索引）。这个文件不存在时直接报错，不再退回旧版本的库；V10 和更早的构建已在 2026-09-30 清理时删除。启动时打印选中的路径。`--db` 指定别的副本。库里没有已审阅的时间事实。
- **人格**：默认 `devtools/canon/amiya_persona.txt`，即 2026-09-26 被精简版替换之前的完整人设。2026-09-28 并入用户原版人设的外貌、说话方式、原作台词分类与“一次不超过三句”（原版的“用括号描述动作”被否决，人设改为明确禁止括号或星号描写），并注明台词只用于把握语气、不照搬；随后去重精简到约 2,500 token（合并版约 4,600），原作台词每类 2 句。精简版已删除。2026-09-29 删去“仍然没有就坦诚说记不清”“拿不准时请坦诚说明不确定”两句，改为“记忆里有的直接说；确实没有的只在那一处说一句没印象”，三句的限制在讲经过和转述档案时放开。
- **对话者**：默认是博士；`--not-doctor` 做身份对照。`--as-of <point_id>` 指定一个已审阅的剧情时间点。
- **模型**：模型类型依次取 `--model-type`、`CANON_CHAT_MODEL_TYPE`、`CANON_MODEL_TYPE` 和 `run_config.py` 的 `MODEL_TYPE`。API key 取自 `CANON_CHAT_API_KEY` 或所选模型的配置，从不打印。
- **观察**：`--show-sources` 或对话中输入 `/sources` 显示证据和路由决定；`--dry-run` 和 `--questions` 不调用对话模型。终端每轮显示证据估算、耗时，以及接口返回的 token 用量。
- **过程记录**：`--trace` 每轮向一个 JSONL 文件追加一行：对话历史、工具调用、证据条目（编号、事件 ID、渠道、出处、时间）、证据全文、讲法、初稿、逐句对齐的问题、修补稿、换回或去掉的句子和最终回复。不填路径时写到 `.dev_data/canon/traces/chat-<时间>.jsonl`。记录含剧情原文，只留在本机，不进 git；不加这个选项时不写任何记录。

## 每轮流程

2026-09-28 起，终端不再用本地规则先选路线、再预取证据。是否回忆、回忆多深、走哪条路径，都由主模型决定。这个做法参考了 Knowledge Arch 插件的 research 工具：先用一个很便宜的范围探查，再执行召回，档位按需选最低。实现在 `core/canon/recall.py` 和 `run_canon_chat.py`。

2026-09-29 起（v1.2.28.sub，“先排后说”），证据的形态和回复的检查改由代码按结构决定：代码先判断这一轮是讲经过、查档案还是问事实，把证据按发生先后编号、换成她自己的口吻放进提示词，模型只负责把它说成话；回复不再交给模型逐句核验，而是由代码逐句对到证据上，只有对不上时才请模型定点修补一次。起因和测量见 [canon 对话质量](canon-dialogue-quality.md) 2026-09-29 一节。

0. **讲法**（`core/canon/query.py` 的 `task_of`，不调模型）：问句里有“经过、复述、怎么回事、之战”这类讲一段经过的说法，或 `is_overview` 认得的综述问法，就是**讲经过**；否则有“档案、资料、履历、生日、种族、体检”这类说法就是**查档案**；其余是**问事实**。两种说法都有时按讲经过算，所以“把那一战的档案复述给我”是讲经过。
1. **组装**：系统提示词由人设、对话者身份、[回忆方式]说明（证据包为空时）或[你的记忆]加[讲法]（有证据时），以及[回复要求]组成，历史对话在 5,000 估算 token 以内挑选完整问答对。系统提示词在每次请求模型之前重新组装，工具刚加进来的记忆只在这里出现一次。
   - **查档案**：问句里点到的名字有档案时（实体名，或“某某医生”里包含的名字，实体表里没有的按档案名匹配），代码直接查档案放进证据包，这一轮不提供工具、不兜底补召回，只调用一次模型。点到的名字都没有档案时，按普通流程由模型决定。
2. **生成**：模型从三档里自己选。工具结果只是一行说明（“想起了 5 段，已按发生先后编号放进[你的记忆]”），证据正文不在工具结果里重复。
   - **不召回**：只有明显不涉及过去经历的话，也就是问候、闲聊、此刻的感受、对博士的回应、本次对话里说过的事，直接回答。罗德岛上的日常近况（天气、饮食、作息）可以自然地聊。问到某个人说过什么、做过什么、多久、几个、为什么、在哪里这类可以核对的细节，即使问法像在聊眼前的事，也要回忆；拿不准是眼前的事还是过去的事时，先回忆，不要凭印象直接回答。
   - **轻量召回**：`canon_recall(depth=light)`，模型选一条路径：
     - `event`：某次具体经过；
     - `reason`：原因或动机；
     - `impression`：她对某人某组织的看法；
     - `arc`：某个人物、地点、组织或篇章的一段经历；
     - `latest`：某人最后知道的情况。给了能识别的人物、地点或组织时，直接取它关联的、她知情的事件里时间最新的几件，不再先按相关度检索（单字名“陈”曾因此只取到 1096 年的一件）；其他情况按相关度检索后再按世界时间从新到旧排；
     - `timeline`：把某件事放上时间轴，返回它所在的月份和前后各两段经历，问到的那一行用 `→` 标出；
     - `recent`：到“现在”为止最近的六段经历，加上最新的三件事的原文。
   - **深度探索**：`canon_recall(depth=deep)`，用于梳理多段经过、前因后果。`arc` 路径会按篇章和场景顺序组成提纲。`reason` 路径的深度回忆另带因果骨架说明：按先后讲，先说起点，再说两三个关键转折，最后说结果；没有原话依据的因果说成她自己的判断。
   - **[你的记忆]的样子**：证据包渲染时按发生先后编号（`CanonReader.sequence`），编号就是先后，例如 `③（伦蒂尼姆大战期间·你亲历）我决定这边交给自己……`：
     - 主线里不是往事的事件按原作叙事顺序和场景内顺序排；往事、活动等其余事件，只有日期直接来自原文、年表或本故事条目，且时间区间和前后两件都不重叠时，才插进这条链；沿用前一场景的日期或没有日期的，放在后面，标“先后不明”。
     - 摘要、原文台词和场景回忆里她的名字换成“我”，玩家占位换成当前称呼。时间轴排在最前，标〔时间轴〕；档案排在最后，标〔档案〕。
     - 原文明说、带引用行的因果和动机边（`CanonReader.causal_links`，V11 全库两端她都知情的有 135 条）列成一行 `〔因果〕原文明说前一件促成了后一件：①→③`，只有这两件事之间才许说“所以、因此”。抽取推断出来的边不算。
     - 原来的〔先后〕行、`DEEP_NOTE` 和 `CAUSAL_NOTE` 已删除：编号本身就是先后，篇幅和叙事结构写在[讲法]里。
   - **讲经过的取证**：都先按相关度找锚点事件，锚点带全部摘要、原文台词和场景回忆。
     - 轻量的 `event`、`reason` 召回（`CanonRecall._incident`）：再取锚点所在场景里她知情、不是往事的相邻事件（前 2 件、后 6 件，`CanonReader.scene_run`），以及其余命中，每件只给一行：题目加摘要最后一句（抽取规则要求最后一句写结果）。
     - `arc` 或 deep 召回（`CanonRecall._storyline`）：锚点之外，接综述检索按篇章和场景排好的提纲，每件一行，一直到结局。事件窗口只到锚点所在场景为止，跨章节的经过需要一直讲到结果。
     - 同样受每轮 2,000 的上限约束。
   - **先想后说（只在讲经过）**：[讲法] 后另加一段 [先想后说]，要求先在 `<提纲>` 里按“起因、经过、结果、感受”逐行只写记忆编号和不超过八个字的提示，再在 `<回答>` 里按块展开，把所引记忆里的具体人、动作、原话要点讲出来。代码只把 `<回答>` 交给检查和博士（`spoken`）；提纲里某块只写了“无”时，用“问题 + 这一块要找的内容”补查一次，补到新记忆就重写一次（`empty_blocks`）。问事实、问原因不写提纲：在 55 题上加提纲没有提升，问事实反而略降。
   - **[讲法]**：讲经过时不受人设三句的限制，用一段话讲清楚（约 150–300 字）：先一句点出是哪件事，再按编号讲起因、经过和结果，编号之间用“后来、接着”连接，只有〔因果〕一行列出的两件事之间才说“所以”，其他原因说成“在我看来”，最后可以说一句此刻的感受；问事实时先直接回答，再用一两句交代当时的情况；查档案时说成“档案上写着”，档案里没写的就说没写。

   `timeline` 和 `recent` 只在库里有世界日历坐标时提供（见 [canon 时间线与事实有效期](canon-temporal-facts.md) 的“世界日历坐标”），工具说明里同时写明“现在”是什么时候。时间轴每行是“时间 故事名：两个事件题目”，只列她知情、且不晚于“现在”的事件，经汇报或听说得知的会标出；整段作为证据 `T1` 进入证据包，计入同一份预算，检查时也能对上。

   **时间说法**：模型看到的时间不是泰拉历，而是原作里的大事件（时间锚点）。
     - 锚点表是 `core/canon/character.py` 的 `ANCHORS`，挂在角色画像上；逻辑在 `core/canon/anchors.py`。每个锚点有她说出口的简称、正式事件名、按关卡编号划的剧情范围、上一级锚点和一段世界时间。现有 24 个，从卡兹戴尔内战到泽尔格勒事件。卡西安号兵变阿米娅一件都不知道，《洪炉示岁》是片中剧本、不是世界里发生的事，两者都不当锚点；她一件都不知道的锚点在加载时丢掉。
     - 事件所在场景落在某个锚点的剧情范围里，就用最具体的那个锚点：“伦蒂尼姆大战期间”“霜星阵亡时”“博士救阿米娅前后”。往事不按所在章节算；原文、年表或本故事给出的直接日期离锚点时间两年以上的，也视为插叙，不算。
     - 其余有日期的事件按离它最近的顶层锚点来说：完全落在其中说“期间”；只知道年份、和锚点同年说“那一年”；区间交叠说“前后”；否则说“之后约两个月”“以前约十七年”。只知道年份的不细到月份，一年以内说“一年内”。
     - “现在”也这样说，例如“现在大约是泽尔格勒事件刚结束的时候”。时间轴每行开头的时间用这一行中间那件事的说法。
     - 属于当前一段时间（`is_recent`）的证据在时间后面标“最近”，例如 `〔E1〕（泽尔格勒事件期间·最近·你亲历）`；提示词要求说别人现在的情况只能依据标着“最近”的片段。
     - 回复要求多一条：说时间照括号里的说法，不说出年份、月份或日期。检查看的是同一份证据渲染，模型自己报出的年份在对上的记忆里查不到，会标为数字问题。
     - 日历仍在底下：排序、“最近”、先后行、`latest` 的排序和 `--trace` 的 `when` 都用日历，trace 另记模型看到的 `said`。库里没有对得上的关卡编号时（例如 20 场景 Nexus 库）退回日历标签，也不加这条回复要求。
     - 没有日期的回忆仍标“往事”。V11 全库上阿米娅知情的事件里，每条时间标签平均从约 4 个 token 变成约 8 个。
     - 库里还有几处日期是错的（巴别塔、《去咧嘴谷》、15-1/15-2 沿用的日期、第 16 章的夏秋顺序），会让按日期定位的少数事件和排序出错；这些留给单独一轮修 `event_times`，见 `docs/TODO.md`。
   拿不准查谁时，可以先调 `canon_probe`。它只返回问题里点到的人物、地点、组织、篇章，她知情的事件数，以及主要出现的篇章，不含原文，约几十 token。实体表里“凯尔希医生”这类带称谓的名字，按其中包含的、知情事件更多的名字统计。`operator_archive` 照旧。每轮最多两次工具往返，工具往返不写入历史。
   `subject` 只在它是实体表里的名字时才用来收窄召回；写成篇章名、几个词或库里没有的名字时不再过滤，只按 `query` 检索。此前这样写会把所有候选都筛掉：两个版本合计 164 次带 `subject` 的召回里，14 次的 `subject` 不是实体名，其中 10 次落空。召回一无所获时，工具结果按情况区分：本轮还没有任何记忆，就提示换更具体的名字或不填 `subject` 再试一次；已经有记忆，就只根据已有的回答。
   工具最多两轮（`canon_probe` 也算一轮）。两轮用完后模型还会被再问一次：这一次仍带工具说明但 `tool_choice` 设为 `none`，并在最后一条工具结果后加一句“回忆次数已用完，不要再调用工具；只根据[你的记忆]直接回答”；接口不接受 `tool_choice` 时改为不带工具。回复为空，或夹着工具调用标记（DeepSeek 的 DSML、`<tool_call>` 等）时，追加一句“请直接用中文回答，不要输出任何工具调用”再重试一次。
   **兜底补召回**：模型一次 `canon_recall` 都没调用（只探查，或完全没用工具），而且证据包里什么都没有（查过档案就不算）时，用本地路由器（`plan_turn` 和 `route`）再看一遍问句；判为故事问题（lane 是 canon 或 status）就替它补一次召回，路径按路由器的判断：综述用 `arc` 加 `deep`，问原因用 `reason`，问看法用 `impression`，问某人现状且点到人物用 `latest`，其余用 `event`。取到证据后，带着记忆再生成一次回答，再进入检查，多一次模型调用；trace 的“调用工具”里会出现“兜底补召回”。闲聊不受影响；模型自己召回过就不补；`--no-tools` 对照模式不补。
3. **检查**（`core/canon/gateway.py` 的 `check_reply`、`inspect`）：
   - 本轮没有用到回忆证据时不检查，一轮只调用一次模型；不再删结尾提问或出戏句，这些靠提示词。
   - 用到回忆时，回复里提到、证据包里没有的名字先按名补查一次（不调模型，可超出每轮预算最多 `VERIFY_EXTRA` = 400）。然后代码把每句话按两字词的重合对到最像的那条记忆（重合占这句自身两字词的三成以上才算对上），不调用模型，逐句找这些问题：
     - 名字：提到的人物、地点、组织在证据包里没有，也不是对话者自己说过的；
     - 数字：数字加量词（“三支”“十五分钟”“1098年”）不在对上的那条记忆里，阿拉伯数字和汉字数字都认；
     - 说过头：“所有人、全部、全都、大家都、一个都、无一、唯一”不在对上的那条记忆里；
     - 引号：引号里的话在证据和对话里找不到原句；
     - 先后：句首是“后来、随后、接着”这类词，对上的记忆编号却比上一句的小；句首是“在那之前、此前”，编号却更大；
     - 因果：句首是“所以、因此、于是、因而、这才”，上一句和这一句对上的是两件不同的事，〔因果〕里没有这一对，也没有“在我看来、我觉得”这类判断的说法；句中的“因为……”“也因此”属于同一件事，不算；
     - 否认：说“记不清、不记得、没印象、需要一点时间、无法直接给”之类，而对上的记忆里有这部分；讲经过时，或查档案且查到了档案时，对不上任何记忆的否认句也算；
     - 客套收尾：最后两句里的“如果您……我可以……”“随时”“尽力”这类说法；
     - 旧事说成现在：句子带“现在、目前、如今、至今、最近”并点到了人物，对上的记忆却不属于最近；“还在、依然”只表示持续，不算，句中有“当时、那时”或“现在”出现在“说、提到、告诉”之后（转述别人的话）也不算；
     - 出戏：出现原作、剧情、章节、数据库、游戏术语这类词。

     词表只用来找候选，判断靠证据的结构（编号、〔因果〕、“最近”标记、对上的是哪条记忆）。
   - 没有问题就原样提交。有问题时调用一次模型定点修补：把回复逐句编号，列出要改的句子和原因，要求只改这些句子、其余一字不改、保留原来的连接，只用[你的记忆]里有的内容，记忆里没有的就不提，也不加记不清之类的声明。
   - 修补稿再按同样的方法检查一遍（不调模型）。仍有问题的句子换成它对上的那条记忆自己的最后一个完整句子（她的口吻，当面称博士为“您”）；对不上任何记忆、又没法替换的，才不要这一句。代码不改写任何措辞，也不再补接连接词、给列表重新编号。
   - 原来的逐句核验模板（`supported / contradicted / uncovered`、`link`、`now`）、按句补查、整段连贯修订、复核、二次定点修订、`mend()` 补接和 `tidy()` 删句都已删除。
4. **提交**：只把最终回复写进内存历史。

统计行显示本轮档位（比如“档位：轻量召回（latest「凯尔希」）”“档位：查档案（凯尔希）”）和讲法，以及工具调用、按名补查、对齐（每类问题几句）、是否定点修补、换回记忆原句和去掉的句数、模型调用次数、证据 token 和耗时；问题句前标问题类别，例如 `[先后]`、`[否认记得的事]`。`--dry-run` 不调用模型，只打印这句话的范围探查结果。

本地规则路线（`core/canon/query.py` 的 `plan_turn` / `route`、`EvidenceAssembler.prefetch`）不再用于终端，只保留给离线检索题库评测（`devtools/canon/retrieval.py`、`bench_bank.py`），用来衡量同一检索栈的召回质量。

## 证据预算

- `--token-budget`（默认 2000 估算 token，即 `core/canon/recall.py` 的 `TURN_BUDGET`；2026-09-28 从 900 调整，第二轮扫描后锚定，防护测试钉住这个值）是**每轮原文预算的硬上限**：本轮所有 `canon_recall` 和 `operator_archive` 共用它，累计不超过它，也不再自动放宽。人设、规则和历史对话不计入。唯一的例外是检查前按回复里的名字补查，它可以在这之上再加最多 `VERIFY_EXTRA = 400`（防护测试钉住）：深度回忆常把 2000 用满，不留余地就补不到；而从 2000 里预留，会让初稿能用的证据变少。所以初稿仍然不超过 2000，统计行里超出的部分标“含补查”。
- 每次召回都可以用到本轮剩余预算；轻量召回每次最多取 5 个事件，深度探索会组篇章提纲或多跳扩展。第一次扫描发现，把轻量召回限制在一半会让多数轮次只用到预算的一半，太紧的上限还会逼出额外的召回轮，所以取消了这个限制。预算用完后，工具会告诉模型只根据已有记忆回答。
- 深度探索的回答不受人设“一次不超过三句”的限制，用一段话讲清主要经过（约 150–300 字）。工具结果、人设和修订提示词都说明了这一点。
- **预算扫描（2026-09-28）**：`devtools/canon/budget_sweep.py` 用真实终端流程跑 40 道题 × 7 档预算（200–3000），评审模型对照参考答案打分；`budget_sweep_report.py` 按档汇总。V11 全库、KCL arc:chat 上的结果（每组合只跑一次，95% 区间宽约 ±0.13）：
  - 准确度 200 档 0.31，400 档跳到 0.50，400–3000 之间是平台（0.43–0.58），2000 档最高（0.58；事实细节类 0.64）；
  - 延迟中位数在 400 档以上都是 4.8–6.3 秒，不随预算上升；
  - 3000 档的 P90 用量（1,948）和 2000 档（1,926）几乎一样，约 2000 是实际需求的天花板。

  建议值 2000，已改为默认值。第一次扫描的编造判定有缺陷：评审是同一个模型，而且看不到原文，把参考答案之外的真实细节也算作编造（抽查 3 条，3 条都是原文里真实存在的）。所以第二轮改为：
  - 评审用 `arc:nexus`，和被测的 `arc:chat` 分开；它和 `arc:apex` 在同一组校准例子上判定完全一致，单次 2–14 秒（`arc:apex` 20–36 秒）；
  - 题库改为 `sweep-bank-v2.jsonl`，由 Claude 审定：每题带原文行、前后约 20 行上下文、答案要点、原文证实的正例、被指定原文推翻的反例，以及知情情况；
  - 幻觉只指与原文矛盾或与反例相同的说法，找不到依据但也不矛盾的说法单独记为无依据；
  - 先顺序跑完全部回答，再并发评审，评审不干扰延迟测量。

  评审在 6 个已知答案上校准，全部判对。

  **第二轮结果**（40 题 × 6 档，共 240 轮）：“罗德岛和陈的合作变化”一题在 5 档上评审连续超时，整题剔除，每档 n=39，95% 区间宽约 ±0.15。
  - 准确度：400 档 0.42，700 档 0.45，1000 档 0.47，1500 档 0.47，2000 档 0.58，3000 档 0.56。
  - 幻觉率 5–10%，不随预算上升。第一轮看到的约 25% 编造率来自评审方法。
  - 每轮召回 1.03–1.21 次，延迟中位数 4.3–7.0 秒，都不随预算变化。预算收紧不会逼出更多召回轮。
  - 召回时平均用掉预算的 86–94%（400–1500 档）。2000 档召回时用 1,509，3000 档用 1,550，被每次 5 个事件、每个事件 4 行的取数上限卡住。要让更大的预算起作用，得放宽取数上限。
  - 16 条幻觉里有 7 条是在场或收到过汇报却说“没收到”“不在场”。剧情题里 33/162 次回答以“记不清”收尾，平均 0.11 分。模型选择不召回的 9 次剧情题全是 0 分。综述题在各档只有 0.1–0.4。

  结论：每轮预算锚定在 2000。之后的准确度问题出在检索命中、错误否认知情和不召回，不在预算。原始结果和汇总放在构建目录的 `canon.sweep/` 下，图表见机制说明页。
- 插件配置里的 `canon_token_budget`（默认 600）是给尚未实现的 B7 注入路径准备的，两者的关系还没确定，见 [canon 运行时结构](canon-runtime-architecture.md)。

## 检索

终端用 SQLite `mode=ro` 和 `query_only=ON` 读取数据库（可看到已提交的 WAL 内容），不调用会建表或更新 meta 的 `CanonStore.open()`。对话历史只保存在内存；不加 `--trace` 时，单轮试聊不创建聊天记录、基准报告或日志，`--questions` 则创建本地检索评测报告。终端滚屏与远程模型服务方的请求留存由各自环境决定。发送给生成模型的内容包括当前问题、有限的内存历史、人格提示词和本轮命中的 canon 片段。

检索默认 `--retrieval auto`：这份库在所属构建目录里有派生向量索引（`<构建目录>/canon.retrieval/index-<哈希>.sqlite`，由 `moirai canon retrieval build --allow-remote --db <库>` 生成）时用 hybrid，没有时用离线的 baseline。hybrid 用加权 RRF（k=10）融合四路：向量 1.0、事件文本（主题、摘要、参与者、beats）的两字 BM25 0.3、原文台词的两字 BM25 0.8、实体 0.1；baseline 融合后三路，再做本地加权。两份 BM25 都是启动时在内存里建的，库内的 trigram 全文表（`events_fts`、`beats_fts`）和由 `import --embed` 写入的 `event_vec` 表都不参与终端检索。`--dry-run` 不加 `--allow-remote` 时始终离线。

有上限的结构扩展会沿事件关系边和原文场景的前后衔接最多走两跳，最多返回六个上下文事件、每个场景至多三个，不额外调用向量或模型。它用在四个地方：情境综述从最强的命中事件出发；明确综述从前四个命中出发（印象题不扩展）；“为什么”类问题从前两个命中出发补两个事件；点名关系的问题为关系那一路补一个事件。抽取出的因果边和场景相邻只是导航线索，不证明世界时间、因果或角色知情。上限的具体数字见 [canon 对话质量](canon-dialogue-quality.md) 的 Retrieval and knowledge boundaries 一节。

## 综述路线

综述路线由 `core/canon/overview.py` 负责意图判断和跨场景选择。它从同一库的场景锚点、篇章名、官方简介、episode 与事件文本定位候选范围；篇章资料只用于导航，送进证据包的事实仍来自事件摘要和原文行。一次综述检索最多发一次向量查询，其余篇章聚合与多样性选择在本地完成；明确的长剧情综述最多选十六个事件，先按篇章与场景原文顺序加入带出处的短提纲，再按相关度填入每事件至多四条原文行；印象和情境综述仍最多选十个事件、两条原文行。终端里由模型用 `canon_recall` 的 `arc` / `impression` 路径调用它，工具返回结构化的范围、代表性覆盖说明，以及带事件 ID、原文行键和知情渠道的证据，受本轮同一份原文预算约束（见“证据预算”）。评测报告的 `overview_trace` 保留范围、候选、最终事件和原文行键。它是 Moirai 内部的模型工具接口，目前没有独立 MCP 服务或 Bot 运行时接入。

## 档案查询（operator_archive）

干员档案、NPC 情报和敌人图鉴在世界观里是罗德岛的人事档案和作战情报，是剧中存在的记录，所以作为阿米娅可以查阅的资料接入；星级、职业、技能、数值、卡池这类只有玩家才有的信息不导入，也仍按出戏处理。数据来自 Arknights-Texts v7 的 `exports/archive_pack/`（干员 434、NPC 5、敌人 948，敌人只收 BOSS 和精英），按 archive_hash 增量导入，不调用模型：

```bash
python -m core.canon.cli archive-import --pack ../Arknights-Texts/exports/archive_pack \
    --story-pack ../Arknights-Texts/exports/story_pack --db <canon.sqlite>
```

`--story-pack` 同时按新的实体种子刷新实体：补新实体和别名、更正种子实体的类型（如只以说话人身份出现的“整合运动”改为组织）、重写种子实体的 `entity_archives` 档案链接；抽取出的同名实体不动。schema_version 4 新增 `archives`、`archive_sections`、`entity_archives`，旧库打开时原地升级。

`operator_archive(name, section)` 由模型自行调用：先按别名找到实体再取它挂的档案，找不到时按档案名或英文代号匹配，干员档案排在敌人图鉴前面，每次最多两份档案、每份最多两段、每段最多 600 字。不指定段落时返回基础档案和客观履历（NPC 为情报资料一，敌人为作战情报），并列出这份档案还能查的段落。默认只返回档案本体形态的段落：升变档案（`PATCH` 解锁）、属于其他形态的段落（`patchIdList` 里没有这份档案本身）和标题为“？？？”的隐藏段都不返回，`--archive-all` 才全部返回；档案是游戏里的最新版本，可能超过阿米娅“当下”应知道的范围，这是保守默认的原因。查到的段落以 A 编号放进同一个证据包，在[你的记忆]里标〔档案〕，排在事件之后，回复要求让她说成“档案上写着”。2026-09-29 起，讲法判为查档案、点到的名字又有档案时，代码直接按上面的规则查，不经过模型的工具调用，这一轮只调用一次模型（见“每轮流程”第 1 步）。

## 批量检索评测

现有自动检索题库可直接通过同一个 `test` 入口批量运行，不调用生成模型。省略 `--questions` 后面的路径时使用 `../Arknights-Texts/eval/canon_retrieval_bank.jsonl`（200 题：细节 99、场景召回 66、跨事件大问题 20、闲聊 15；原名 `retrieval-200-v3-audited.jsonl`，字段说明见 Arknights-Texts 的 README，数据从私有 HF 数据集 `ProjectOedipus/Arknights-Amiya` 获取）；每题独立检索，不沿用上一题的聊天历史。大问题各标三个原文支持的剧情要点，报告单列要点召回与至少覆盖两个要点的比例。全量库可这样测：

```bash
moirai canon test --questions
```

批量评测默认用离线 baseline；`--retrieval hybrid --allow-remote` 需要这份库对应的派生向量索引，并会向配置的 embedding 服务发送查询。先用 `moirai canon retrieval plan --db <canon.sqlite>` 估算，再显式运行 `moirai canon retrieval build --allow-remote --db <canon.sqlite>` 建索引。`--out <报告.json>` 可指定报告位置；未指定时报告写入这份库旁的 `canon.retrieval/runs/`。报告逐题记录路线、命中、最终和注入排名，并汇总最终召回、注入召回、答案行注入率与闲聊路线正确率。大问题的三个要点是选定的代表性证据，其他相关事件可能同样有用；要点覆盖率是严格的锚点指标，不等同于最终回答质量。这 200 题在开发中都用过，融合权重和路线阈值也在它上面调过，分数偏乐观，只适合做改动前后的回归对比。旧的 `retrieval-200-v1`、`retrieval-100-v2` 等题库已在 2026-09-30 删除。

回答质量评测用 `devtools/canon/budget_sweep.py`，默认题库是 `../Arknights-Texts/eval/canon_answer_bank.jsonl`（55 题，原名 `sweep-bank-v4.jsonl`）。`devtools/canon/sweep_wrap.py` 用指定代码目录自己的 `budget_sweep` 跑一次扫描，给跨章节题（kind 为 cross）另加因果和先后的评审规则，并可跳过指定题的评审；`devtools/canon/sweep_compare.py` 把后面各次评审结果和第一次逐题配对比较，给出分差、bootstrap 区间以及幻觉和延迟的拆分。

请把试聊中发现的无关召回和回答问题记录下来，在 B6–B9 的正式 Bot 路径再验证。
